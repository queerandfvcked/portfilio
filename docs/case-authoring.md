# Как устроен кейс в портфолио: архитектура, схема данных, блоки

Документ для генерации нового кейса «под паттерны» проекта. Ниже — полная карта: из каких файлов собирается страница кейса, какие поля обязательны, какие блоки контента разрешены, каким языком и какой структурой пишутся главы.

Стек: React 18 + Vite + react-router, контент лежит в JS-объектах (не в CMS, не в MDX). Кейс = запись в реестре + две локали текста (ru/en).

## 1. Из чего собирается страница кейса

```
URL: /ru/<slug>  и  /en/<slug>
        │
App.jsx (CASE_SLUGS, роутинг)
        │
CaseStudy.jsx  ── CaseNavigation (TOC слева)
        │        ├─ case-hero: eyebrow (domain) + title + description + links + CaseScene
        │        ├─ case-meta: role / platform / scope / status
        │        ├─ case-stats: плитки цифр (stats)
        │        ├─ case-tldr: «За 20 секунд» (problem / solution / result)
        │        ├─ CaseChapter × N:
        │        │     label + title + lead + body
        │        │     body = RegularSection → formatContent(content)
        │        │            ├─ обычный текст (legacy-рендер)
        │        │            └─ :::блоки (case-blocks/*)
        │        └─ CaseChapter «Что я понял» (takeaways → CaseRows)
        │
CaseStudyData.js  (сборка объекта кейса из переводов)
        │
LanguageContext.jsx  (ru/en: тексты, мета, stats, tldr, takeaways, projectsList)
        │
seo/meta.js + scripts/prerender.mjs  (title/description, OG, hreflang, статичные html)
```

Ключевой принцип: **структура страницы задаётся в `CaseStudyData.js`, тексты — в `LanguageContext.jsx`, порядок глав — порядком объектов в массиве `sections`**. Номер главы (`01 · ПРОБЛЕМА`) считается автоматически по индексу.

## 2. Схема объекта кейса (`src/components/CaseStudyData.js`)

Ключи верхнего уровня — slug'и в kebab-case: `zhabka`, `keepl-app`, `keepl-landing`, `hired-app`, `add-transition`.

| Поле | Тип | Обяз. | Что делает |
| --- | --- | --- | --- |
| `title` | string | да | H1 в hero. |
| `subtitle` | string | нет | Фолбэк для eyebrow, если в `projectsList` нет `domain`. Обычно `Web & Mobile`. |
| `description` | string | да | Абзац под H1. 1–2 предложения, что за продукт и роль. |
| `tags` | string[] | нет | Есть в данных, визуально почти не используется. |
| `heroImage` | string | да | Картинка-фолбэк, если для кейса нет `CASE_MEDIA`. |
| `heroImages` | string[] | нет | Доп. кадры (используются не везде). |
| `meta.role` | string | да | Значение строки «Роль». Обычно `t('casePage.roleValue')`. |
| `meta.platform` | string | нет | Фолбэк, если в `projectsList` нет `platform`. |
| `meta.scope` | string | нет | Фолбэк, если в `projectsList` нет `scope`. |
| `meta.status` | string | нет | Статус («MVP, до запуска»). |
| `stats` | `{value,label}[]` | нет | Плитки под hero. 2–3 штуки (в макете помещается до 4). |
| `links` | `{label,href,kind,external}[]` | нет | Кнопки в hero. `kind: 'primary' | 'ghost'`; `external:true` → `<a target=_blank>`, иначе внутренний `Link` (href без языкового префикса). |
| `takeaways` | `{title,text}[]` | нет | Отдельная глава «Что я понял» после всех секций (получает следующий номер). 2–3 пункта. |
| `tldr` | `{problem,solution,result}` | нет | Блок «За 20 секунд». Показывается, только если все три строки непустые. |
| `sections` | Section[] | да | Главы. |

### Section

| Поле | Тип | Обяз. | Что делает |
| --- | --- | --- | --- |
| `id` | string | да | Anchor (`#id`), kebab-case, уникальный в кейсе. Участвует в deep-link и TOC. |
| `title` | string | да | Заголовок главы. 4–9 слов, одна фраза в `*звёздочках*`. |
| `label` | string | нет | Моно-метка в шапке: `ПРОБЛЕМА`, `PRODUCT DISCOVERY`, `UI`. Пишется КАПСОМ, 1–2 слова. Если нет — останется только номер. |
| `nav` | string | нет | Короткая подпись в левом TOC. Если нет — берётся `label`, затем `title`. |
| `lead` | string | нет | Вводный абзац под заголовком. 1–3 предложения. Поддерживает `*акцент*`. |
| `content` | string | нет | Тело главы: обычный текст + `:::` блоки (см. §4). |
| `images` | string[] | нет | Доп. картинки под телом (кликабельные). Подпись = `title` без звёздочек. |
| `collapsible` | boolean | нет | Сворачиваемая глава (deep dive). |
| `defaultOpen` | boolean | нет | Открыта ли сворачиваемая глава по умолчанию (обычно `false`). |
| `landingLinks` | `{label,href,kind,external}[]` | нет | Кнопки внизу главы (используется в главе «Лендинг» кейса Keepl). |

Особенности рендера:

- Глава без `content`/`images`/`landingLinks` выводит только шапку — это нормально для глав-разделителей, но обычно так не делают.
- Если в кейсе есть хоть одна `collapsible`-глава, сверху появляется тулбар «Развернуть всё / Свернуть всё».
- `takeaways` всегда идут отдельной главой после всех секций и получают следующий порядковый номер.
- `stats` и `tldr` — только на уровне кейса; внутри текста для цифр есть блок `:::stats`.

## 3. Тексты (`src/contexts/LanguageContext.jsx`)

Структура: `translations.ru` и `translations.en`, внутри — одинаковый набор ключей. Для кейса нужны четыре блока:

```
ru.projectsList[]                        → карточка на главной
ru.casePage.cases.<slug>                 → role, status, stats[], takeaways[]
ru.casePage.tldr.<slug>                  → problem, solution, result
ru.caseStudies.<camelCase>               → title, subtitle, description, tags[], sections[]
```

Правила:

- Ключ в `caseStudies` — camelCase (`zhabka`, `keeplApp`, `hiredApp`, `keeplLanding`, `addTransition`), а slug — kebab-case (`keepl-app`). В `CaseStudyData.js` они связываются вручную.
- `sections` в переводах — массив той же длины, что и `sections` в данных. `CaseStudyData.js` обращается к индексам явно (`sections.0`, `sections.7`), поэтому порядок в массиве переводов и порядок вывода на странице могут не совпадать (так сделано в Zhabka: «Стек» — 7-я запись, но выводится 6-й главой).
- В `ru` и `en` структура обязана совпадать: одинаковое число секций, одинаковые индексы, одинаковый набор полей. Отличается только текст.
- `content` — шаблонный литерал (`` ` ``), многострочный. Внутри нельзя использовать обратные кавычки и `${` без экранирования.
- Необязательные поля (`label`, `nav`, `lead`, `images`) можно не писать вовсе: `tx()` вернёт `undefined`, и поле просто не отрендерится.
- `t(key)` возвращает сам ключ, если перевода нет, поэтому опечатка в ключе выглядит как `caseStudies.myCase.title` на странице.

### `projectsList` (карточка на главной)

| Поле | Тип | Обяз. | Примечание |
| --- | --- | --- | --- |
| `id` | string | да | = slug кейса. |
| `title` | string | да | Полное название. |
| `cardTitle` | string | нет | Короткое для карточки. |
| `summary` | string | да | 1–2 предложения для карточки. |
| `description` | string | да | Для карточки/мета. |
| `link` | string | да | `/<slug>` без языкового префикса. |
| `variant` | `'wide' | 'compact'` | да | `wide` — большая карточка с ноутбуком+телефоном, `compact` — обычная с обложкой. На главной сначала идут все `wide`, затем `compact` сеткой. |
| `domain` | string[] | да | Eyebrow карточки и страницы, соединяется через ` · `. |
| `platform` | string | да | Строка «Платформа» в карточке и в meta кейса. |
| `scope` | string | да | Строка «Что делал». |
| `highlight` | `{value,label}` | нет | Крупная цифра на карточке. |
| `badge` | string | нет | Бейдж поверх обложки (например `Хакатон → MVP`). |

Порядок массива = порядок карточек внутри своей группы (`wide` / `compact`) и состав блока «Другие кейсы» (первые 3, кроме текущего и `keepl-landing`).

## 4. DSL контента

`content` поддерживает два слоя.

### 4.1. Обычный текст (legacy-рендер)

| Синтаксис | Результат |
| --- | --- |
| `## Заголовок` | h2, акцентный |
| `### Заголовок` | h3 |
| `#### Заголовок` | h4 |
| `**жирный**` | semibold-акцент внутри абзаца |
| `- пункт` / `• пункт` | маркированный список |
| `\| a \| b \|` + строка `\|---\|---\|` | таблица (первая строка — заголовок) |
| пустая строка | разделитель абзацев, отступов не даёт |

Не использовать: `# h1`, `[ссылки](...)`, `![img](...)`, вложенные списки, цитаты `>`, code fences. Ссылки — только через `links` кейса или `:::embed`.

**Акцент `*слово*` работает только в `title` и `lead` главы** — в `content` звёздочки останутся как есть.

### 4.2. Блоки `:::`

Открытие: `:::name attrs`, закрытие: строка с `:::` на отдельной строке. Блоки не вкладываются. Незакрытый блок остаётся обычным текстом. Текст между блоками рендерится legacy-слоем.

| Блок | Назначение | Синтаксис |
| --- | --- | --- |
| `callout` | Крупный вывод с моно-меткой | `:::callout label="Гипотеза"` + абзац |
| `cards` | Сетка карточек | `:::cards cols=2\|3\|4 [numbered] [featured\|featured=both]`, строки `**Заголовок** \| текст` |
| `triad` | Три колонки со стрелками | `:::triad labels="Когда\|Хочу\|Чтобы"`, строки `a \| b \| c` |
| `stats` | Плитки цифр | `:::stats`, строки `значение \| подпись` |
| `quad` | Матрица 2×2 | `:::quad axes="INTERNAL\|EXTERNAL\|TECHNICAL\|PRODUCT"`, 4 строки `Заголовок \| текст` |
| `steps` | Цепочка шагов | `:::steps`, строки `Шаг` или `Заголовок \| текст` |
| `steps-tabs` | Шаги по сценариям с вкладками | `:::steps-tabs`, `# Сценарий`, далее шаги |
| `chain` | Причинно-следственная цепочка | `:::chain`, 3–5 строк-узлов |
| `chips` | Ряд моно-чипов | `:::chips`, строка(и) через запятую |
| `rows` | Строки-карточки с ромбом | `:::rows`, `**Заголовок.** текст` или `Фраза. текст` |
| `findings` | «Хорошо / Ошибка» с картинкой | `:::findings`, строки `good\|mistake \| Заголовок \| текст \| /assets/...` |
| `gallery` | Сетка картинок с подписями | `:::gallery cols=2\|3`, строки `/assets/x.webp \| Подпись` |
| `stage` | Сцена для 1–3 картинок | `:::stage layout=single\|pair\|trio`, строки `путь \| Подпись` |
| `slider` | Слайдер картинок | `:::slider`, строки `путь \| Короткая метка` |
| `flow` | Схема узлов и петель | `:::flow`, `circle\|square\|diamond \| Заголовок \| текст`, петли `loop 3>2 \| подпись` |
| `embed` | iframe с белым списком | `:::embed url="https://embed.figma.com/..." ratio=16:9 mobileratio=4:5 maxwidth=800 title="..."` |

Детали, которые легко сломать:

- В строках блоков разделитель — `|`; у картинок режется **только по первому** `|`, поэтому пробелы в путях допустимы: `/assets/zhabka/mob inbox chat.webp | Мобильная версия`.
- `cards`: `numbered` без `featured` — просто нумерация; `featured` — первая карточка на всю ширину; `featured=both` — ещё и последняя (рассчитано на 5–7 карточек).
- Картинки в `gallery`, `stage` и `slider` кликабельны и открывают лайтбокс (`openImageModal`); `gallery` — это сетка одиночных `stage` с подписями.
- `slider`: подпись строки = метка слайда, держать короткой («Десктоп», «Мобильная версия»); лишние атрибуты игнорируются.
- `embed`: разрешены только `embed.figma.com`, `www.figma.com/embed`, `cdn.knightlab.com`; `title` обязателен; для Figma `sandbox` не ставится.
- `flow`: индексы в `loop` — 1-based по порядку узлов; 3–5 узлов оптимально.
- `stats` внутри главы — про метрики; `stats` кейса — про hero. Не дублировать одни и те же цифры.

## 5. Как писать главы (паттерны существующих кейсов)

### Нарратив

Рабочий каркас (7–12 глав):

1. **Проблема / Контекст** — что не работает и почему это боль. Без ретроспективного «я молодец».
2. **Задача / Гипотеза** — что именно проектируем и как поймём, что получилось.
3. **Исследование** (опционально) — интервью, конкуренты, JTBD, инсайты.
4. **Решение / Механика** — как продукт работает, `:::flow` + экраны.
5. **Решения** — 3–6 продуктовых решений карточками, каждое с причиной.
6. **UI / Экраны** — интерфейс, адаптив, состояния.
7. **Метрики / Результат** — цифры, честная пометка, что не измерено.
8. **Что дальше** — 2–4 направления.
9. **Стек** (опционально, для собранных проектов) — `:::chips` по слоям.

### Формат главы

- `label`: 1–2 слова капсом, по-русски или общепринятый английский термин (`PRODUCT DISCOVERY`, `JTBD`, `USER FLOW`, `UI`).
- `nav`: то же, но в человеческом регистре и короче (`Product Discovery`, `Что дальше`).
- `title`: 4–9 слов, одна смысловая фраза в `*акценте*` (1–3 слова). Без точки в конце.
  - `Вакансии тонули в *шуме* Telegram-каналов`
  - `Не агрегатор, а персональный *AI-секретарь*`
  - `Бинарная оценка превращает цели в *рутину* и чувство вины`
- `lead`: 1–3 предложения, 180–450 знаков. Сначала ситуация, потом вывод. Именно здесь живёт главная мысль главы.
- `content`: блок-первый. 1–3 блока на главу + короткие связки между ними. Не превращать в стену текста: абзац → блок → один вывод.
- Экраны: десктоп+мобайл — `:::stage layout=pair`; несколько состояний — `:::gallery`; пошаговый флоу — `:::slider` или `:::steps-tabs`; один ключевой экран — `:::stage layout=single`.
- Подписи к картинкам — что смотреть, а не «скриншот 1».

### Тон и типографика

- Первое лицо, прошедшее время, активные глаголы: «переработал», «проверил», «решил».
- Каждое решение объясняется через «почему», а не через «сделал красиво».
- Честность про валидацию: если метрик нет — прямо писать «влияние не измерено», «план валидации описан».
- Цифры: `≈170`, диапазоны через короткое тире `5–10`, `2–3`, проценты `≈4%`.
- Кавычки «ёлочки», длинное тире `—`, неразрывные пробелы не обязательны.
- Английские термины не переводятся искусственно: `JTBD`, `retention`, `drop-off`, `PWA`.
- В `lead` и `title` акцент ставится на смысловое слово, не на служебное.

### Мета-тексты

- `description`: 1–2 предложения, что за продукт + что сделал автор.
- `tldr.problem` / `solution` / `result`: по одному предложению, 90–160 знаков, без воды; `result` — с цифрой, если она есть.
- `takeaways`: 2–3 пункта `{title, text}`; title — вывод в 3–6 слов, text — почему это важно.
- `stats`: 2–3 пары; `value` — короткий (цифра/диапазон), `label` — 2–5 слов.
- SEO (`src/seo/meta.js`): title `Название — кейс | Andrian Shtark` (en: `case study`), description до ~160 знаков.

## 6. Чек-лист регистрации нового кейса

Slug один и тот же во всех местах, kebab-case (`my-case`). Ниже — 6 обязательных точек + 3 опциональные.

### 6.1. Ассеты

| Что | Куда | Формат |
| --- | --- | --- |
| Картинки внутри глав | `public/assets/<slug>/` | WebP, ширина ≤1600px, q≈75. Путь в контенте: `/assets/<slug>/screen.webp`. |
| Обложка карточки / мокапы для `CaseScene` | исходники в `assets-src/case-main/`, нарезка скриптом в `public/assets/case-main/` | PNG с альфой для мокапов, JPG-фолбэк для непрозрачных обложек. Имена: `<name>-800/1200/1600/2000.webp`. |
| OG-картинка | `public/og-image.jpg` | Общая для всех страниц, менять не нужно. |

Правила: имена файлов — латиница, kebab-case, без пробелов (старые кейсы с пробелами — наследие, повторять не надо); для ретины достаточно 1600px, потому что картинки глав рендерятся обычным `<img>` без `srcset`; всё, что тяжелее ~300 kB, лучше пережать.

Проверка: `npm run dev` → `/ru/<slug>` и `/en/<slug>`; TOC, deep-link `#<section-id>`, лайтбокс картинок, мобильная ширина; затем `npm run build` (внутри — SSR + prerender).

## 8. Частые ошибки

1. **Несинхронные индексы.** Добавили главу в переводы, но не в `CaseStudyData.js` (или наоборот) — на странице будет `caseStudies.myCase.sections.5.title` вместо заголовка.
2. **Разные структуры ru/en.** Пропущенная секция в `en` ломает нумерацию и TOC.
3. **Забытый `CASE_SLUGS`.** Страница работает в dev, но не собирается в статику (prerender) и не попадает в SEO.
4. **`*акцент*` в `content`.** Работает только в `title` и `lead`.
5. **Вложенные или незакрытые `:::`.** Незакрытый блок молча становится текстом с `:::callout` в абзаце.
6. **`|` в тексте карточек/строк.** Ломает разбиение: используйте запятую или тире.
7. **Несуществующий путь к картинке.** Битых ссылок сборка не ловит — проверять глазами.
8. **Дубли `id` секций.** Ломают anchor-навигацию и подсветку TOC.
9. **Слишком длинный `lead`.** Он становится вторым заголовком; 3 предложения — предел.
10. **Придуманные метрики.** В проекте принято явно писать, что не измерено.

## 9. Что не нужно делать при генерации кейса

- Не добавлять новые React-компоненты, CSS или зависимости: всё уже есть в `src/components/case-blocks/`.
- Не использовать legacy-маркеры из `formatCaseContent.jsx` (`LAYOUT_START`, `*_IMAGES_START`) — это исторические костыли старого кейса.
- Не использовать `:::embed` для сторонних хостов вне белого списка.
- Не менять `case-blocks.css` под конкретный кейс.
- Не трогать главу с `id: 'motion-states'`: для неё в `CaseRegularSection.jsx` жёстко подключена анимация Жабки (только Zhabka).
